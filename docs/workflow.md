# NutriSight 서비스 워크플로우

**상태**: 팀 제안안 (팀 결정 전) · **기준 문서**: [기획안](proposal.md) · **작성일**: 2026-11-26 · **갱신**: 2026-11-27

> 하루 파일럿의 세부는 [하루 파일럿 설계 전 검토](pilot-design-review.md)(화면 4개, 처방 추천, 기술 구성, 경고 규칙), [시스템 구조](system-architecture.md)(흐름, 사진 처리 상태, API), [데이터 모델](data-model.md)(테이블, 상태 값, 결정 사항)에 정리했다. 이 문서와 다르면 그 문서들이 최신이다.

기획안을 구현하기 전에 서비스의 사용자, 역할, 흐름을 정리한 문서다. 기획안과 달라진 제안은 [기획안 대비 변경점](#기획안-대비-변경점)에 모아 둔다.

## 서비스 목표

의료진이 요양병원 환자의 **영양 섭취 상태를 추적**하고, 그에 맞는 **의료 조치를 처방**할 수 있게 한다. 시스템은 섭취 추이와 경고, 근거 자료 기반 처방 추천을 제공하고, 조치의 판단과 확정은 의사가 한다.

## 대상과 역할

- **대상 환자**: 요양병원에서 **일반식**을 먹는 환자 (파일럿 범위)
- **파일럿 형태**: 별도 촬영 장비 없이, 개인 기기로 사진을 찍어 업로드한다. 로그인·권한은 두지 않고, 화면에서 역할을 고르는 것은 화면 구분일 뿐이다.
- **배식 가정**: 모든 대상 환자는 같은 일반식을 메뉴별 표준 배식량으로 받는다. 식판은 6칸(밥, 국, 주찬, 부찬 2, 김치) 고정 배치다.

| 역할 | 화면 | 하는 일 |
| --- | --- | --- |
| **영양사** | ① 기준 식전 업로드 (모바일) | 끼니마다 표준 배식 식판 1장을 기준 식전 사진으로 촬영해 업로드한다. |
| **요양보호사** | ② 식후 업로드 (모바일) | 개인 기기로 환자별 식후 식판을 촬영해 업로드한다. 전량 거부·전량 미섭취는 사진 대신 버튼으로 기록한다. |
| **의사** | ③ 환자별 대시보드 + 대화 (PC) | 환자별 섭취 추이와 경고를 확인하고, 추천을 검토·수정해 처방을 확정한다. |
| (시연) | ④ 처리 상태 대시보드 (PC) | 사진별 처리 단계와 실패를 보고 재시도한다. |

## 사전 준비 (기준 데이터)

파일럿은 아래 데이터를 시드 스크립트로 미리 넣는다. 입력·수정 화면은 만들지 않는다.

1. **환자** — 일반식 대상 환자(가명)와 체중 이력, 하루 목표량 이력, 평가 기록(MNA-SF, 씹기·삼킴 등).
2. **배식 계획** — 날짜·끼니별 6칸 구성: 칸 위치 → 메뉴, 메뉴별 **표준 배식량**(저울 실측)과 그 양 기준의 에너지·단백질(식약처 식품영양성분 데이터). 칸 위치로 메뉴가 정해지므로 메뉴 인식은 하지 않는다. 간식은 넣지 않는다.
3. **발주** — 환자 × 끼니별 식사 발주: 식사 범주·코드, 발주 상태(`ordered` / `npo` 금식 / `cancelled` 외출·퇴원 등), 특이사항.
4. **모의 이력** — 가상 환자의 1~2주 섭취 기록. 시연에서 올린 끼니가 그 뒤에 이어진다.

## 끼니별 흐름

1. **기준 식전 사진 (영양사)** — 끼니마다 표준 배식 식판 1장을 촬영해, 날짜·끼니를 선택하고 올린다. 칸별 "배식 직후" 상태의 기준이 된다. 다시 올리면 새 사진으로 바꾸고 그 끼니의 식후 분석을 모두 다시 한다.
2. **식후 촬영·업로드 (요양보호사)** — 환자, 날짜·끼니를 선택하고 환자별 식후 식판 사진을 올린다. 금식·취소 환자는 회색 배지로 표시되고 고를 수 없다. 환자가 전량 거부했거나 식판을 받고 전혀 먹지 않았으면 "전량 거부"·"전량 미섭취" 버튼으로 기록한다(사진 없이 모든 칸 0%).
3. **분석 (시스템)** — VLM이 식후 사진의 각 칸을 기준 식전 사진의 같은 칸과 비교해 칸별 섭취율(0~1, 10% 단위)을 추정한다. 칸 섭취량은 섭취율 × 그 칸의 표준 배식량 기준 에너지·단백질이다. 이어서 일별 집계와 경고를 다시 계산하고, 경고 수준이 올라가면 처방 추천을 만든다.
4. **상태 구분 (시스템)**
   - 식후 사진이 없는 끼니는 `미기록`이다.
   - 기준 식전 사진이 없는 끼니는 분석을 보류하고, 기준 사진이 올라오면 자동으로 분석한다.
   - 칸 하나가 가려지는 등 판단할 수 없으면 그 칸만 `판단 불가`로 두고 나머지로 합계를 낸다(추정 불완전 표시).
   - 사진 전체를 판단할 수 없으면 `재촬영 필요`로 안내한다.
   - 직원이 칸별 섭취율을 직접 입력하는 기능은 두지 않는다.

## 추적과 처방 흐름 (의사)

1. **추적** — 환자별로 끼니·일 단위 에너지·단백질 섭취를 **하루 목표량** 대비 %로 본다. 목표는 진료팀 설정값이 있으면 그것을, 없으면 체중 기반 ESPEN(30 kcal/kg, 단백질 1.0 g/kg), 체중이 없으면 한국인 영양소 섭취기준(성별·연령)으로 정한다. 하루 %는 간식을 뺀 3끼 기준이고, 미기록·금식 끼니가 있으면 기록된 끼니로 환산해 "1/3끼"처럼 표시한다.
2. **경고** — 섭취 부족 위험을 `주의`(최근 7일 평균 75% 미만)와 `경고`(50% 이하인 날이 연속 5일 이상)로 표시한다. 판정은 매일 최근 7일로 다시 하고, 기준에 걸린 영양소를 함께 보여 준다(예: "주의 · 단백질 61%"). 미기록 끼니는 평균에서 빼고 미기록 수를 함께 보여 준다. 전량 거부·전량 미섭취는 0 섭취로 포함하고, 금식·취소 끼니는 평균에서도 미기록 수에서도 뺀다.
3. **처방 추천** — 경고 수준이 올라가면 시스템이 근거 자료(가이드라인)를 바탕으로 추천 카드를 만든다. 의사는 같은 화면의 환자 전용 대화에서 근거를 묻고 카드를 고칠 수 있으며, 처방 유형을 골라 항목을 직접 추가·수정할 수 있다.
4. **처방 확정** — 의사가 카드에서 항목을 골라 확정한다. 추천 카드가 없는 환자에게도 처방을 직접 작성해 확정할 수 있다. 확정된 처방은 바꾸지 않는다. 시스템(에이전트)은 처방을 확정할 수 없다.
5. **효과 확인** — 처방 시점을 추이 화면에 표시해 처방 전후의 섭취 변화를 비교한다.

```
[사전 준비] 환자 · 배식 계획 · 발주 · 모의 이력 (시드)
      │
      ▼
[영양사] 기준 식전 사진 1장 (끼니당)
[요양보호사] 환자별 식후 사진 업로드 · 또는 전량 거부/미섭취 기록
      │
      ▼
[시스템] 칸 위치로 메뉴 대응 · VLM 섭취율 추정 · 에너지/단백질 환산
         · 일별 집계 · 경고 판정 · (경고 수준 상승 시) 처방 추천
      │
      ▼
[의사] 섭취 추이 확인 ─▶ 경고 ─▶ 추천 검토·대화·수정 ─▶ 처방 확정 ─▶ 처방 후 추이 확인
                 ▲                                                          │
                 └──────────────────────────────────────────────────────────┘
```

## 제안 사항

| 항목 | 제안 | 이유 |
| --- | --- | --- |
| 촬영 방식 | 개인 기기로 촬영 후 업로드 | 파일럿 프로젝트로, 고정 촬영 장비를 두지 않는다. |
| 사진과 환자·끼니 연결 | 기준 식전은 화면 ①에서 날짜·끼니, 식후는 화면 ②에서 환자와 날짜·끼니를 선택 | 구현이 가장 단순하고 파일럿에 충분하다. |
| 사용자 역할 | 기준 사진은 영양사, 식후 사진은 요양보호사, 결과 확인과 처방은 의사 | 현장 업무 분담을 반영한다. |
| 처방에서 시스템의 범위 | 추적·경고, 근거 자료 기반 처방 추천, 의사 승인으로 처방 확정 | 조치 판단과 확정은 의사가 하고, 시스템은 추천과 근거, 처방 후 변화를 보여준다. |
| 대상 식사 | 일반식만 | 메뉴와 표준 배식량이 정해져 있어 섭취량을 계산할 수 있다. |
| 섭취량 추정 | VLM으로 기준 식전·식후 사진을 칸별 비교 | 각도 차이, 양념 자국, 국을 모델이 함께 판단한다. 상세는 [시스템 구조](system-architecture.md) 5절. |
| 경고 기준 | 환자별 하루 목표 대비 에너지·단백질 섭취 (주의: 7일 평균 75% 미만, 경고: 50% 이하 연속 5일) | 국내외 기준 근거. 상세는 [설계 전 검토](pilot-design-review.md#5-섭취-부족-경고-규칙-제안), 목표 결정 규칙은 [데이터 모델](data-model.md) 2절. 처음 제안(배식 계획 급여량 대비)을 대체한다. |
| 하루 섭취 범위 | 간식 제외, 3끼 기준 | 간식은 식판 사진 분석 대상이 아니다. 실제보다 낮게 잡힐 수 있어 화면에 함께 표시한다. |
| 메뉴 식별 | 배식 계획의 식판 내 칸 위치로 정한다 | 6칸 고정 배치이므로 메뉴 인식 모델이 필요 없다. |
| 배식량 | 메뉴별 표준 배식량을 모든 환자에게 적용한다 | 모든 환자가 같은 일반식을 받는다고 가정한다. |
| 식전 사진 | 끼니당 기준 식판 1장 | 배식이 같다고 가정하므로 환자별 식전 사진이 필요 없다. 촬영 부담이 절반으로 줄고 식전·식후 짝짓기 실수가 없다. |
| 직원 입력 | 칸별 섭취율 입력은 두지 않고, 끼니 단위 전량 거부·전량 미섭취만 기록 | 사진 없이 0을 확인하는 경우만 받아 미기록과 구분한다. |

## 기획안 대비 변경점

- **결과 확인자**: 영양사 → 의사(파일럿 화면 기준).
- **서비스 목표**: 섭취 기록 확인 → 섭취 추적, 경고, 처방 추천·확정, 처방 효과 확인까지.
- **처방식 조회 (기획안 추가 기능)**: 대상이 일반식으로 좁혀져 제외 후보다.
- **메뉴 인식**: 기획안의 PyTorch 메뉴 인식과 AI Hub 데이터는 필수에서 빠진다. 메뉴는 칸 위치로 정한다.
- **섭취량 추정**: 기획안의 영역 면적비(OpenCV)·MLP 대신 VLM 칸별 비교를 쓴다.
- **식전 사진**: 환자별 식전·식후 2장 → 끼니당 기준 식전 1장 + 환자별 식후 1장.
- **촬영 조건**: 기획안은 "같은 식판을 같은 구도에서 촬영"을 전제했다. 개인 기기로 촬영하면 구도가 달라질 수 있다.

## 열린 문제

1. **촬영 구도 차이** — 개인 기기로 찍은 식전·식후 사진의 각도·거리·조명 차이를 VLM이 어디까지 감당하는지 저울 실측 식판으로 확인한다. 부족하면 촬영 가이드(화면 오버레이 등)를 더한다. 판단할 수 없는 칸·사진은 품질 문제(`angle` 등)와 함께 판단 불가로 돌린다.
2. **표준과 다른 배식** — 실제 담긴 양이 표준과 다르면 오차가 생긴다. 파일럿은 가정으로 받아들이고, 필요하면 식후 사진에서 이상치를 표시하는 방안을 검토한다.
3. **처방식 조회 기능** — 범위에서 뺄지 확정해야 한다.

다음 문제는 다른 문서에서 제안안으로 정리했다.

- 경고 임계값·판단 단위·연속 횟수, 경고 대상 영양소(에너지·단백질) → [설계 전 검토](pilot-design-review.md) 5절
- 배식 계획 데이터 형식 → 시드 스크립트로 입력, 영양성분은 식약처 데이터 ([데이터 모델](data-model.md) 3절)
- 처방 기록 항목과 처방 유형 7개 → [데이터 모델](data-model.md) 6절
