# NutriSight 서비스 워크플로우

**상태**: 초안 · **기준 문서**: [기획안](proposal.md) · **작성일**: 2026-11-26

기획안을 구현하기 전에 서비스의 사용자, 역할, 흐름을 정리한 문서다. 기획안과 달라진 결정은 [기획안 대비 변경점](#기획안-대비-변경점)에 모아 둔다.

## 서비스 목표

의료진이 요양병원 환자의 **영양 섭취 상태를 추적**하고, 그에 맞는 **의료 조치를 처방**할 수 있게 한다. 시스템은 섭취 추이와 경고를 제공하고, 조치의 판단은 의료진이 한다.

## 대상과 역할

- **대상 환자**: 요양병원에서 **일반식**을 먹는 환자 (파일럿 범위)
- **파일럿 형태**: 별도 촬영 장비 없이, 개인 기기로 사진을 찍어 업로드한다.

| 역할 | 하는 일 |
| --- | --- |
| **요양보호사** | 개인 기기로 식전·식후 식판을 촬영해 업로드한다. |
| **의료진** | 환자별 섭취 추이와 경고를 확인하고, 조치를 판단해 처방을 기록한다. |

## 사전 준비 (기준 데이터)

1. **환자 등록** — 일반식 대상 환자 목록을 등록한다.
2. **배식 계획 등록** — 날짜·끼니별 메뉴, 메뉴별 표준 배식량, 끼니별 계획 열량과 영양소별 급여량을 등록한다.

## 끼니별 흐름 (요양보호사)

1. **식전 촬영·업로드** — 업로드 화면에서 환자, 날짜·끼니, `식전`을 선택하고 식판 사진을 올린다.
2. **식후 촬영·업로드** — 같은 방식으로 `식후`를 선택해 올린다.
3. **분석 (시스템)** — 두 사진에서 식판의 같은 칸을 맞추고 메뉴별 섭취율을 추정한다. 배식 계획의 급여량을 적용해 열량과 영양소 섭취량을 계산한다.
4. **누락 구분 (시스템)** — 식후 사진이 없는 끼니는 `미기록`, 식후에 칸이 비어 있으면 `완식`으로 구분한다.

## 추적과 처방 흐름 (의료진)

1. **추적** — 환자별로 끼니·일 단위 섭취 추이를 배식 계획의 급여량과 비교해 본다.
2. **경고** — 계획 급여량 대비 실제 섭취가 기준에 못 미치는 환자를 경고 목록에 표시한다.
3. **처방 기록** — 의료진이 판단한 조치(예: 보충식, 식사 형태 변경, 영양 상담)를 환자 기록에 남긴다.
4. **효과 확인** — 처방 시점을 추이 화면에 표시해 처방 전후의 섭취 변화를 비교한다.

```
[사전 준비] 환자 등록 · 배식 계획 등록
      │
      ▼
[요양보호사] 식전 업로드 ─▶ 식후 업로드
      │
      ▼
[시스템] 칸 대응 · 메뉴별 섭취율 추정 · 열량/영양소 환산 · 누락 구분
      │
      ▼
[의료진] 섭취 추이 확인 ─▶ 경고 ─▶ 처방 기록 ─▶ 처방 후 추이 확인
                 ▲                                   │
                 └───────────────────────────────────┘
```

## 결정 사항

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 촬영 방식 | 개인 기기로 촬영 후 업로드 | 파일럿 프로젝트로, 고정 촬영 장비를 두지 않는다. |
| 사진과 환자·끼니 연결 | 업로드 화면에서 환자, 날짜·끼니, 식전/식후를 선택 | 구현이 가장 단순하고 파일럿에 충분하다. |
| 사용자 역할 | 촬영자는 요양보호사, 결과 확인자는 의료진 | 현장 업무 분담을 반영한다. |
| 처방에서 시스템의 범위 | 추적·경고를 제공하고 처방은 기록만 한다 | 조치 판단은 의료진이 하고, 시스템은 판단 근거와 처방 후 변화를 보여준다. |
| 대상 식사 | 일반식만 | 메뉴와 표준 배식량이 정해져 있어 계획 대비 섭취를 계산할 수 있다. |
| 경고 기준 | 배식 계획의 열량·영양소별 급여량 대비 실제 섭취량 | 배식 계획에 끼니별 계획 급여량이 있다. |

## 기획안 대비 변경점

- **결과 확인자**: 영양사 → 의료진(영양사 포함).
- **서비스 목표**: 섭취 기록 확인 → 섭취 추적, 경고, 처방 기록, 처방 효과 확인까지.
- **처방식 조회 (기획안 추가 기능)**: 대상이 일반식으로 좁혀져 제외 후보다.
- **촬영 조건**: 기획안은 "같은 식판을 같은 구도에서 촬영"을 전제했다. 개인 기기로 촬영하면 구도가 달라질 수 있다.

## 열린 문제

1. **촬영 구도 차이** — 개인 기기로 찍은 식전·식후 사진의 각도·거리·조명 차이를 촬영 가이드(화면 오버레이 등)로 줄일지, 사진 정렬 알고리즘으로 보정할지 정해야 한다.
2. **경고 임계값** — 계획 대비 몇 % 미만을 저조로 볼지, 판단 단위(끼니 또는 하루), 연속 횟수를 정해야 한다.
3. **경고 대상 영양소** — 열량 외에 어떤 영양소(단백질 등)를 경고에 쓸지 정해야 한다.
4. **배식 계획 데이터 형식** — 병원 식단표를 어떤 형식(CSV, 수기 입력 등)으로 받고, 메뉴별 급여량이 포함되는지 확인해야 한다.
5. **처방 기록 항목** — 처방 유형 목록과 기록 필드(처방자, 시점, 내용, 기간)를 정해야 한다.
6. **처방식 조회 기능** — 범위에서 뺄지 확정해야 한다.
