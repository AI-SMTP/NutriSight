1. 문제와 프로젝트 목표
요양병원 식단표에는 제공한 메뉴와 배식량이 남는다. 환자가 실제로 먹은 양과 영양소를 파악하려면 식사 후 어떤 메뉴가 얼마나 남았는지 확인해야 한다. 식판을 절반씩 남겨도 밥을 남긴 환자와 단백질 반찬을 남긴 환자의 섭취량은 다를 수 있다. 식사 거부를 확인한 경우와 식후 기록이 누락된 경우도 각각 다른 정보다.

NutriSight는 영양사가 등록한 끼니별 기준 식전 사진과 요양보호사가 올린 환자별 식후 사진을 비교한다. 메뉴별 섭취율을 추정해 에너지·단백질 섭취 이력으로 쌓고, 섭취 부족 위험을 표시한다. 의사는 환자 대시보드에서 섭취 추이와 공개 가이드라인에 근거한 영양중재 제안을 확인하고, 환자별 대화에서 근거를 질문하거나 제안을 수정해 모의 처방을 확정한다.

하루 파일럿의 목표는 모의 식판 사진과 가상 환자 기록으로 사진 등록 → 섭취율 추정 → 섭취 부족 경고 → 근거가 있는 추천 카드 → 의사 역할의 모의 처방 확정이 한 흐름으로 동작하는지 확인하는 것이다. 기능 검증에는 사진 샘플과 기대 결과가 정해진 모의 입력을 사용한다. 표시 수치는 등록된 배식 표준값에 따른 추정치이며, 실제 환자 적용에는 별도 현장·임상 검증이 필요하다. 파일럿 설계 및 범위

3. 섭취율 추정과 영양 계산
1. 사진 연결 — 기준 식전 사진은 날짜·끼니별 배식 계획에, 식후 사진은 해당 환자의 한 끼 발주(meal_order_id)에 연결한다. 등록된 칸 정보에서 메뉴명·위치·표준 배식값을 읽는다.
2. VLM 추정 — 기준 식전 사진, 식후 사진, 식판 배치를 입력해 slot_id, intake_fraction_est, status, quality_issues를 칸별로 반환한다. 섭취율은 0~1을 0.1 단위로 반환한다. 배식된 음식이 그대로 남으면 0, 다 비웠으면 1이다. 가림, 흐림, 각도 차이 등으로 값이 불분명하면 None과 사유를 반환한다. 결과에 VLM 어댑터 이름을 남긴다.
3. 영양 환산 — 메뉴별로 등록된 제공 영양량 × 칸별 추정 섭취율을 계산한다. 제공 단백질 10 g인 반찬을 40% 섭취했다면 약 4 g으로 기록한다. 판단 불가 칸은 합계에서 빼고 해당 끼니를 incomplete로 표시한다. 식판 전체가 판단 불가이면 미확인 끼니로 처리한다.
4. 데이터 출처 — 기존 모의 섭취 이력, 시연 중 등록한 사진, 직원이 확인한 0% 기록을 구분한다. 사진 처리에는 팀이 준비한 모의 식판 이미지를 사용한다. 배식 계획의 제공량과 영양성분은 시드에 등록된 표준값을 사용한다. 섭취 추정 인터페이스와 영양 모듈 · 모의 데이터 출처 및 변환
4. 하루 목표와 섭취 부족 경고
하루 목표량은 그날 적용된 진료팀 설정값 → 체중 기반 기본값 → 2025 한국인 영양소 섭취기준의 성별·연령 참고값 순서로 선택한다. 체중 기반 구현값은 에너지 30 kcal/kg/일, 단백질 1.0 g/kg/일이다. 시드에 포함된 10명은 진료팀 설정값을 사용하며, 대시보드에서 각 목표의 출처를 확인할 수 있다. 데이터 모델 · ESPEN 지침 · 2025 한국인 영양소 섭취기준
입력 상태	영양 집계 처리
섭취가 기록된 끼니 / 직원이 확인한 전량 거부·전량 미섭취	기록 끼니에 포함한다. 전량 거부·미섭취의 섭취량은 0이다.
미기록 / 사진 전체 판단 불가 / 분석 실패	기록 끼니에서 제외하고 미기록 수에 포함한다.

하루 목표 대비 환산율(%) = 기록된 끼니 섭취 합계 × (3 ÷ 기록 끼니 수) ÷ 그날 목표량 × 100. 예를 들어 목표 1,500 kcal인 환자가 한 끼 400 kcal를 기록했다면 합계는 400 kcal, 하루 목표 대비 환산율은 80%다. 화면에 기록 범위 1/3끼를 함께 보여주고, 기록된 끼니가 없으면 일별 환산율을 비워 둔다. 일별 환산 및 미기록 표시

판정은 매일 최근 7일을 기준으로 다시 계산한다. 환산율이 없는 날에는 연속 일수를 이어 세지 않는다. 경고와 주의가 모두 해당하면 경고를 우선 표시하며, 경고를 유발한 영양소와 근거 기간·수치, 미기록 수를 함께 제공한다. 이 규칙의 용도는 섭취 부족 위험을 표시해 의료진 검토를 돕는 것이다. AND/ASPEN과 GLIM은 임계값 설계에 참고한 자료이며, 단백질에 같은 임계값을 적용하는 것은 파일럿 규칙이다. 경고 설계 · AND/ASPEN · GLIM
5. 근거 검색과 모의 처방 흐름
- 자동 추천 — 경고 수준이 올라갈 때, 선택된 환자의 최근 섭취 추이·목표·경고·평가를 바탕으로 가이드라인을 검색하고 추천 카드를 저장한다. 각 항목에 제안 내용, 관련 문서와 절, 확인이 필요한 점을 표시한다. 동일한 경고가 계속되면 기존 카드를 유지하고, 의사가 필요할 때 다시 생성한다.
- 검색 자료 — ESPEN 노인 영양 실무 지침, 「고령자의 영양 관리」, GLIM 5년 업데이트, 병원간호사회 욕창간호 실무지침을 사용한다. 초기 검색은 문서의 절 단위로 나눈 본문에 BM25를 적용한다. 입력 기록이나 가이드라인 근거가 부족하면 확인에 필요한 정보가 무엇인지 카드에 적는다. RAG 자료 목록
- 추천 유형 — 식사 강화, 경구영양보충(ONS), 식사 형태 변경, 간식 추가, 영양 상담·다학제 의뢰, 재평가·관찰, 기타.
- 대화와 확정 — 에이전트는 환자 섭취 요약 조회, 근거 검색, 추천 초안 수정 도구를 사용한다. 환자별로 대화 스레드를 분리한다. 의사 역할의 사용자는 추천 항목을 고치거나 추가한 뒤 원하는 항목을 확정할 수 있다. 모의 처방에는 최종 내용, 확정 시점, 연결된 추천을 저장한다. 추천·처방 데이터 모델 · 에이전트 및 API 설계
6. 기술 구성과 개발 순서
FastAPI + React/Vite + SQLite로 대표자 PC에서 실행한다. 시스템 처리와 채팅의 진행 상태는 서버 전송 이벤트(SSE)로 화면에 전달한다. 분석·영양 계산·추천 모듈은 같은 백엔드 프로세스에서 동작하며, 라우터와 에이전트는 필요한 서비스 함수를 공유한다. 사진은 로컬 폴더에 보관하고, 대화 체크포인트는 별도 SQLite 파일에 저장한다. 시스템 구조

7. 모의 데이터와 시연 완료 기준
시드는 NS01~NS10의 가상 환자 프로필, 체중·영양 목표·평가 정보와 7일간의 식사 이력으로 구성한다. 시연일을 D0로 두고 과거 D-7~D-1을 불러온다. D0에는 배식 계획과 환자별 발주를 미리 넣고, 섭취 기록은 시연 중에 생성한다. 시연 시드 JSON · 시연 환자 구성
점검 항목	완료 기준
사진과 칸 매칭	기준 식전·식후 사진을 올리면 같은 배식 계획으로 연결된다. 분석 가능한 식판은 환자별 결과에 6칸이 각각 한 번씩 나오고, 판단하기 어려운 칸은 사유를 확인할 수 있다.
영양 계산과 경고	칸별 모의 섭취율을 넣었을 때 에너지·단백질 합계와 하루 환산율이 손계산과 일치한다. 75% 경계, 50% 경계, 4일·5일 연속, 전량 거부·미기록·금식 구분을 확인한다.
사진 품질과 예외 흐름	완식·부분 섭취·남김을 연출한 모의 사진으로 결과를 확인한다. 기준 사진이 늦게 등록되는 경우, 판단 불가, 분석 실패와 재시도에서 화면 상태가 갱신된다.
통합 시연	대표자 PC에서 새 식후 기록이 섭취 이력에 붙고, 위험 수준 상승과 추천 카드 생성이 이어진다. 선택한 환자의 카드 근거를 조회하고, 의사 역할로 수정·확정한 내용이 처방 이력에 남는다.


대표 시연은 NS03이다. D-1까지 에너지 섭취가 목표 대비 50% 이하인 날이 4일 연속이다. D0 아침의 6칸 섭취율이 모두 30%인 테스트 결과를 사용하면, 제공량 698 kcal에서 기록된 섭취량은 209.4 kcal이고 하루 목표 1,700 kcal 대비 환산율은 **약 37%(1/3끼)**다. 에너지 섭취가 5일 연속 기준 이하로 기록되면서 주의 → 경고 → 추천 카드 생성 → 모의 처방 확정을 보여줄 수 있다. 37%는 현재 아침 배식 데이터와 정해진 테스트 입력의 검산값이다. 시드 배식값 · NS03 시연 이력

보조 시연은 NS02의 단백질 단독 주의, NS09의 D-1 경고, NS06의 전량 거부, NS01의 금식, NS08의 미기록으로 확인한다. 시연 환자 구성
